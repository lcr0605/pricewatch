# AI(Claude Code) 활용 기록

Claude Code로 개발하면서 AI에게 맡긴 작업과, 결과를 검토해 직접 고친 부분을 기록합니다.

## 2주차 · 가격 변동 분석 + 일일 보고서
- **맡긴 작업:** 오늘/직전 가격 비교 SQL, 판정 규칙(급변·목표가·30일 최저·판매처 급감·가격 갭), 텔레그램 보고서 템플릿
- **요구사항으로 준 조건:** 유료 API 금지, 숫자는 코드가 계산, 목표가 알림은 처음 도달한 날만, 텔레그램 길이 제한 대응
- **검토하며 고친 점**
  1. **첫 수집일 문구 오류:** 실제 DB로 보고서를 만들어 보니, 비교할 어제 데이터가 없는데 "40개 모두 가격 변동이 없습니다"라고 출력됨 → 담당자가 오해할 수 있어 "첫 수집일이라 비교 불가"로 구분 (`compared` 인자 추가, 테스트 추가)
  2. **테스트 기대값 오류:** 길이 제한 테스트가 실제 출력 문구(`… (이하 대시보드에서 확인)`)와 다른 문자열을 기대해 실패 → 기대값 수정
- **결과:** 테스트 33개 통과, 실제 DB 데이터로 보고서 출력 확인

## 2주차 · 다나와 링크로 추적 시작 (대시보드·CLI 공용 로직)
- **맡긴 작업:** 링크에서 상품코드 추출, 등록·해제 로직(`app/tracking.py`), CLI 재작성
- **요구사항으로 준 조건:** 대시보드에서 재사용할 수 있게 화면과 로직 분리, 다나와 요청 최소화, 50개 상한, 해제해도 기록 보존
- **검토하며 고친 점**
  1. **불필요한 다나와 요청:** 실제 DB로 확인하던 중, 이미 추적 중인 상품을 다시 추가하면 CLI가 미리보기를 위해 다나와에 요청하는 것을 발견 → `is_tracking`으로 먼저 확인해 생략
  2. **import 문법 오류:** 테스트 파일 import 정리 중 이름 하나가 괄호 밖으로 빠짐 → 수정
- **병합 충돌 해결:** PR #1(보고서)과 PR #2(링크 등록)가 `CLAUDE.md` 명령 목록과 `repo.py` 끝부분에 각자 내용을 추가해 충돌 → 어느 쪽도 버리지 않고 양쪽 함수·명령을 모두 유지, 합친 뒤 테스트 55개와 실제 DB 조회로 확인

## 3주차 · 토스 스타일 대시보드
- **맡긴 작업:** FastAPI 라우트, 로그인·CSRF, 화면 4개(홈·추적 상품·상세·운영 기록), 링크 → 미리보기 → 추적 시작 흐름, 테스트
- **요구사항으로 준 조건:** 토스 디자인(인상 빨강/인하 파랑), 모바일 우선, 모든 화면 로그인 필수, API 문서 비공개, 다나와 요청 최소화
- **검토하며 고친 점**
  1. **테스트가 실제 다나와에 요청한 문제:** `preview(link, fetch=_default_fetch)`처럼 기본값을 함수 정의 시점에 고정해서, 테스트에서 가짜 함수로 바꿔도 적용되지 않고 존재하지 않는 상품코드로 실제 요청이 나감 → 실행 시점에 기본값을 찾도록 수정 + `tests/conftest.py`에 **테스트 중 외부 요청 차단** 장치 추가
  2. **모바일에서 입력창이 찌그러짐:** 스크린샷으로 확인해 보니 세로 배치(flex-col) 안의 `flex-1` 때문에 입력창 높이가 0에 가깝게 계산됨 → `w-full sm:flex-1`로 수정하고 디자인 규칙에 명시
  3. **홈의 변화 목록을 누를 수 없음:** 판정 결과(Event)에 상품코드가 없어 상세 링크를 만들 수 없었음 → Event에 `pcode` 추가
- **확인:** 테스트 73개 통과, 실제 DB로 로컬 서버를 띄워 화면 5종 스크린샷 확인, 모바일 링크로 실제 미리보기 확인
